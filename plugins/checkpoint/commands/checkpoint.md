# /checkpoint — 세션 상태를 다음 세션으로 넘기는 체크포인트 저장

긴 세션이 끝나갈 때, **다음 세션의 Claude 가 이 파일 한 장만 읽으면 즉시 같은 지점에서 작업을 이어갈 수 있도록** 현재 컨텍스트를 압축해 저장.

## 동작 절차

1. **프로젝트 슬러그 감지** — `basename "$PWD"` (Bash). cwd 의 디렉터리 이름을 slug 로 사용. 비정상이면 `default`.
2. **timestamp 생성** — `date +%Y-%m-%d-%H%M%S` (Bash)
3. **저장 경로 구성**:
   - 아카이브: `~/.claude/checkpoints/<slug>/<timestamp>.md`
   - 최신: `~/.claude/checkpoints/<slug>/latest.md` (같은 내용 덮어쓰기)
4. **체크포인트 본문 작성** — 아래 **표준 포맷** 그대로. 누락된 섹션은 "(없음)" 으로 명시 (헤더는 유지). 거짓말·날조 금지 — 모르면 모른다고 적기.
5. **두 파일 모두 Write 도구로 저장**
6. **사용자에게 반환**:
   - 저장된 경로
   - `/clear` 후 다음 세션에서 그대로 붙여넣을 **한 줄 resume 프롬프트**

## 표준 포맷

```markdown
# Checkpoint — {{프로젝트 slug}} · {{YYYY-MM-DD HH:MM}}

> **다음 세션 Claude 에게**: 이 파일을 읽었다면 §6 "다음 액션" 의 1번을 사용자에게 확인받은 뒤 그대로 진행. 사용자에게 "어디까지 했지?" 묻지 말 것 — 답이 §3, §4 에 있음.

## 1. 한 줄 요약
{{이 세션이 무엇을 향해 갔는지 한 문장}}

## 2. 작업 디렉터리 / 저장소 상태
- cwd: `{{절대경로}}`
- git: `{{branch}}` @ `{{short-sha}}` ({{clean/dirty}}, {{ahead/behind origin}})
- 관련 외부 레포: {{있다면 — 경로와 상태}}

## 3. 이미 한 것 (시간 순)
- {{사실 단위로 — 만든 파일, 내린 결정, 커밋, 푸시 등}}
- ...

## 4. 합의된 결정 / 컨벤션
- {{이 세션에서 확정된 설계 선택·네이밍·범위·제약}}
- {{왜 그 결정인지 한 줄로 이유 첨부 — 다음 세션이 재논쟁 안 하게}}

## 5. 미해결 / 보류
- {{아직 결론 못 낸 항목, "v2 로 미룸" 등}}

## 6. 다음 액션 (우선순위 순, 실행 가능 단위)
1. {{구체 동사로 시작 — 무엇을, 어디서, 결과물은 무엇}}
2. ...
3. ...

## 7. 읽어볼 파일 (resume 시 먼저 열어볼 것)
- `{{경로}}` — {{왜 중요한지 한 줄}}
- ...

## 8. 컨텍스트 단서
- 사용자 톤/선호: {{이 세션에서 드러난 것 — 예: "장황한 요약 싫어함", "단정적 추천 선호"}}
- 활성 스킬/도구: {{쓰고 있던 워크플로, 예: superpowers:brainstorming → 다음은 writing-plans}}
- 환경 메모: {{외부 의존성 상태, 진행 중인 백그라운드 작업 등}}

## 9. 다음 세션에 던질 첫 프롬프트 (사용자가 그대로 붙여넣음)
> "{{한 문장 — 사용자가 다음 턴에 곧장 보낼 프롬프트}}"
```

## 작성 규칙 (중요)

- **사실 우선, 추측 금지** — 한 일은 사실대로, 미래는 액션 항목으로
- **§3 은 압축**: 사고 과정 옮기지 말고 "산출물 + 결정" 만. 단순 명사구 OK
- **§4 는 "왜"가 핵심** — 같은 결정을 다음 세션이 다시 토론하지 않도록 근거 한 줄씩
- **§6 액션은 실행 가능 단위** — "스펙 검토" 가 아니라 "사용자가 docs/.../sherlog-design.md 리뷰하고 수정 의견 줌"
- **§9 첫 프롬프트는 한 문장** — 사용자가 복붙해서 바로 보낼 수 있어야 함
- 답변은 한국어로 (사용자 언어와 일치)
- 같은 정보가 여러 섹션에 중복되면 핵심 섹션 하나에만 남기고 나머지는 짧은 참조로

## 최종 응답 형식

저장 완료 후 사용자에게 **딱 이 형식**으로:

```
저장됨:
- ~/.claude/checkpoints/<slug>/<timestamp>.md
- ~/.claude/checkpoints/<slug>/latest.md (덮어씀)

/clear 후 다음 세션 첫 메시지로:
> 이 체크포인트 읽고 이어서 작업해줘: ~/.claude/checkpoints/<slug>/latest.md
```

장황한 설명, 작업 후기 모두 금지. 두 가지(파일 경로 + 다음 프롬프트)만 분명히.

## 안티패턴

- ❌ 세션 전체 대화를 옮겨 적기 — 압축이 목적. 핵심만
- ❌ 본인이 한 일을 미화/포장 — 사실 그대로
- ❌ §6 액션을 추상적으로 ("코드 짜기") 적기 — 다음 세션이 또 헤매게 됨
- ❌ §9 프롬프트를 두 문장 이상으로 — 한 문장이 원칙
- ❌ `open` 명령으로 파일 자동 열기 — 출력은 텍스트로만
- ❌ "혹시 더 추가할 것 있으세요?" 같은 확인 질문 — 저장은 단호하게 끝내기

## 토큰 효율

체크포인트는 보통 1.5~3K 토큰. 다음 세션은 이 파일 한 장만 읽으면 되므로 초기 30K+ 컨텍스트 재구성을 ~3K 로 줄임. 압축비 10배 이상이 정상.
